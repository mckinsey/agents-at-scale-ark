# Workflow Templates

> **Workflows in Ark are [Argo Workflows](https://argoproj.github.io/workflows/).** Ark does **not** ship its own workflow engine — there's no native "Ark workflow" CRD and no drag-and-drop workflow builder. You author Argo `WorkflowTemplate` / `Workflow` YAML, and each step calls Ark by creating a `Query` resource (or running the `ark` CLI) against an agent, team, model, or tool. Ark provides Helm charts and a pre-built `ark-tools` image to make those calls easy.

## What the dashboard does (and doesn't) do

The dashboard's **Workflow Templates** page is **read-only** — it lists the Argo `WorkflowTemplate`s in your namespace and renders their DAGs so you can see the shape of a pipeline. It is a *viewer*, not an editor:

- ✅ List templates, view details (entrypoint, steps), visualise the DAG (pan/zoom).
- ❌ No creating, editing, or composing workflows in the UI.

**All workflow authoring is YAML.** Write the `WorkflowTemplate`, `kubectl apply` it, and it appears in the dashboard for inspection and in Argo for execution.

## Prerequisites

Workflows require Argo Workflows installed in the cluster:

```bash
helm upgrade --install argo-workflows \
  oci://ghcr.io/mckinsey/agents-at-scale-ark/charts/argo-workflows

# Or, for local development:
cd services/argo-workflows
devspace dev
```

See [Argo Workflows](/developer-guide/workflows/argo-workflows) for the full install, Minio artifact storage, and the Argo dashboard.

## How a step calls Ark

Every Ark interaction inside a workflow is one of two patterns:

1. **The `ark` CLI** — run the pre-built [`ark-tools`](/reference/utility-images#ark-tools) image (ark CLI + kubectl + jq pre-installed) and call `ark query <target> "<message>"`. Simplest for one-shot calls.
2. **A `Query` resource** — `kubectl apply` a `Query` CR, `kubectl wait --for=condition=Completed`, then read `.status.response.content`. Use this when you need labels, TTL, timeout, parameters, or session/conversation IDs.

The examples below show both. They're Argo `template` snippets — drop them into a `WorkflowTemplate`'s `templates:` list.

### 1. Invoke an agent

Using the `ark` CLI:

```yaml
- name: ask-agent
  script:
    image: ghcr.io/mckinsey/agents-at-scale-ark/ark-tools:latest
    command: [bash]
    source: |
      ark query agent/weather-agent "What's the forecast for London?" > /tmp/out.txt
  outputs:
    parameters:
      - name: response
        valueFrom:
          path: /tmp/out.txt
```

### 2. Invoke a team

Same shape — just target `team/<name>`:

```yaml
- name: ask-team
  script:
    image: ghcr.io/mckinsey/agents-at-scale-ark/ark-tools:latest
    command: [bash]
    source: |
      ark query team/research-team "Summarise the latest on EV battery chemistries." > /tmp/out.txt
  outputs:
    parameters:
      - name: response
        valueFrom:
          path: /tmp/out.txt
```

### 3. Invoke a tool

Tools take a JSON object matching their `inputSchema`:

```yaml
- name: call-tool
  script:
    image: ghcr.io/mckinsey/agents-at-scale-ark/ark-tools:latest
    command: [bash]
    source: |
      ark query tool/get-coordinates '{"city":"Paris"}' > /tmp/out.txt
  outputs:
    parameters:
      - name: result
        valueFrom:
          path: /tmp/out.txt
```

### 4. Add session and conversation IDs

To thread several workflow steps into one conversation (shared memory) and group them under a session for telemetry, set `conversationId` and `sessionId`. The `ark` CLI exposes `--conversation-id` / `--session-id`:

```yaml
- name: ask-with-context
  script:
    image: ghcr.io/mckinsey/agents-at-scale-ark/ark-tools:latest
    command: [bash]
    source: |
      ark query agent/assistant "Remember my name is Alice." \
        --conversation-id "{{workflow.name}}" \
        --session-id "{{workflow.name}}"
```

Or, with the `Query` CR pattern, set them in the spec — the workflow name makes a convenient stable ID across steps:

```yaml
- name: ask-with-context
  script:
    image: alpine/k8s:1.28.13
    command: [sh]
    source: |
      QUERY_NAME="step-{{workflow.name}}-$(date +%s%N)"
      cat <<EOF | kubectl apply -f -
      apiVersion: ark.mckinsey.com/v1alpha1
      kind: Query
      metadata:
        name: $QUERY_NAME
        labels:
          workflow: "{{workflow.name}}"
      spec:
        input: "What's my name?"
        conversationId: "{{workflow.name}}"   # shared across steps → same memory thread
        sessionId: "{{workflow.name}}"         # groups the steps for telemetry
        target:
          type: agent
          name: assistant
        serviceAccount: argo-workflow
        timeout: 5m
        ttl: 24h
      EOF
      kubectl wait --for=condition=Completed --timeout=5m query/$QUERY_NAME || true
      kubectl get query $QUERY_NAME -o jsonpath='{.status.response.content}'
```

A later step that reuses the same `conversationId` sees the earlier exchange. See [Run queries → Multi-turn conversations](/user-guide/queries#multi-turn-conversations) for the underlying behaviour.

## Example: agents, teams, and deterministic steps together

Real Ark workflows mix LLM steps (agents/teams) with plain deterministic steps (containers that transform data, gate on conditions, or format output). The marketplace [KYC demo bundle](https://github.com/mckinsey/agents-at-scale-marketplace/tree/main/demos/kyc-demo-bundle) is a good reference: four sequential team steps feeding a final deterministic processing step.

This condensed `WorkflowTemplate` shows the shape — a sequential pipeline where each step queries a different resource, and a final non-LLM step formats the result:

```yaml
apiVersion: argoproj.io/v1alpha1
kind: WorkflowTemplate
metadata:
  name: research-pipeline
  annotations:
    workflows.argoproj.io/description: "Agent → team → deterministic pipeline"
spec:
  entrypoint: main
  serviceAccountName: argo-workflow
  arguments:
    parameters:
      - name: topic
        value: "electric vehicle adoption in Europe"
  templates:
    - name: main
      steps:
        # Step 1 — an AGENT gathers raw material.
        - - name: research
            template: query-ark
            arguments:
              parameters:
                - name: target
                  value: "agent/research-agent"
                - name: input
                  value: "Research: {{workflow.parameters.topic}}"

        # Step 2 — a TEAM reviews and refines, seeing step 1's output.
        - - name: review
            template: query-ark
            arguments:
              parameters:
                - name: target
                  value: "team/review-team"
                - name: input
                  value: "Critique and tighten this research:\n{{steps.research.outputs.parameters.response}}"

        # Step 3 — a DETERMINISTIC step (no LLM) formats the final report.
        - - name: format
            template: format-report
            arguments:
              parameters:
                - name: body
                  value: "{{steps.review.outputs.parameters.response}}"

    # Reusable Ark query step — works for agent/, team/, model/, or tool/ targets.
    - name: query-ark
      inputs:
        parameters:
          - name: target
          - name: input
      script:
        image: ghcr.io/mckinsey/agents-at-scale-ark/ark-tools:latest
        command: [bash]
        source: |
          ark query "{{inputs.parameters.target}}" "{{inputs.parameters.input}}" > /tmp/response.txt
      outputs:
        parameters:
          - name: response
            valueFrom:
              path: /tmp/response.txt

    # A plain container step — pure data transformation, no Ark call.
    - name: format-report
      inputs:
        parameters:
          - name: body
      script:
        image: alpine:3.19
        command: [sh]
        source: |
          echo "# Research Report"
          echo "Generated: $(date -u +%Y-%m-%dT%H:%M:%SZ)"
          echo
          echo "{{inputs.parameters.body}}"
```

Apply it and run it:

```bash
kubectl apply -f research-pipeline.yaml
argo submit --from workflowtemplate/research-pipeline -p topic="EV adoption in Europe"
argo watch @latest
argo logs @latest
```

The template then shows up in the dashboard's Workflow Templates page, where you can view its DAG.

## Bundled samples

The Ark repo ships runnable templates under `services/argo-workflows/samples/`:

| Sample | Shows |
| --- | --- |
| `query-fanout-template.yaml` | List models, fan out a parallel query per model, fan in and compare. |
| `ark-tools-template.yaml` | Run the `ark` CLI in a container and capture output. |
| `weather-workflow-template.yaml` | Sequential agent queries passing results between steps. |
| `a2a-arithmetic-workflow.yaml` | Combine A2A agents, Ark agents, and Python steps. |
| `minio-artifact-template.yaml` | Pass artifacts between steps via Minio. |

```bash
kubectl apply -f services/argo-workflows/samples/query-fanout-template.yaml
argo submit --from workflowtemplate/query-fanout-template -p question="..."
```

For larger end-to-end examples (multi-team DAGs writing reports via the file-gateway), see the marketplace demo bundles: [kyc-demo-bundle](https://github.com/mckinsey/agents-at-scale-marketplace/tree/main/demos/kyc-demo-bundle) and [cobol-modernization-bundle](https://github.com/mckinsey/agents-at-scale-marketplace/tree/main/demos/cobol-modernization-bundle).

## Viewing a template in the dashboard

Once applied, open **Workflow Templates** in the dashboard sidebar to inspect a template:

- **Template list** — name, description (from the `workflows.argoproj.io/description` annotation), creation time.
- **DAG visualisation** — nodes (steps), edges (dependencies), hierarchical top-to-bottom layout, pan and zoom.
- **Template info** — namespace, entrypoint, the available template definitions.

To *run* a template, use the Argo dashboard (**New Workflow → From Template**) or the `argo` CLI — the Ark dashboard only visualises.
