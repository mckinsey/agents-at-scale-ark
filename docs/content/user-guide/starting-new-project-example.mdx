# Complete Worked Example: Customer Support Workflow

This guide walks you through building a functional customer support agent from scratch to deployment. Every YAML snippet in this page is validated against the live Ark CRD schema in CI, so you can copy-paste with confidence.

## Prerequisites

Before starting, make sure you have:

- Ark installed on your cluster (see the [Quickstart](/quickstart))
- `kubectl` configured to talk to that cluster
- A model named `default` available — `ark models create default` if you don't already have one
- `jq` installed locally for the pretty-print steps

Verify quickly:

```bash
kubectl get pods -n ark-system
kubectl get models
```

## What You'll Build

- A customer support agent that answers password reset questions
- A test query to verify the agent works
- Monitoring via the Ark Dashboard
- A second triage agent and a team that combines both

## Step 1: Set Up a Working Directory

Ark doesn't dictate where you keep agent YAML — any directory works. Create one for this example:

```bash
mkdir -p customer-support-bot/{agents,queries,teams}
cd customer-support-bot
```

## Step 2: Create a Support Agent

Write the agent YAML directly:

```bash
cat > agents/support-agent.yaml <<'EOF'
apiVersion: ark.mckinsey.com/v1alpha1
kind: Agent
metadata:
  name: support-agent
spec:
  description: Handles customer support inquiries
  modelRef:
    name: default
  prompt: |
    You are a helpful customer support agent for a SaaS platform.
    Answer customer questions politely, professionally, and concisely.

    Common topics:
    - Password resets
    - Account access
    - Billing questions
    - Feature inquiries
EOF
```

## Step 3: Deploy to Ark

```bash
kubectl apply -f agents/support-agent.yaml
kubectl get agent support-agent
```

Expected status:

```
NAME            PHASE
support-agent   ready
```

## Step 4: Create a Test Query

```bash
cat > queries/test-password-reset.yaml <<'EOF'
apiVersion: ark.mckinsey.com/v1alpha1
kind: Query
metadata:
  name: test-password-reset
spec:
  input: "How do I reset my password?"
  target:
    type: agent
    name: support-agent
EOF

kubectl apply -f queries/test-password-reset.yaml
```

## Step 5: Watch the Query Execute

```bash
kubectl get query test-password-reset -w
```

Expected phase progression (lowercase, per the CRD):

```
NAME                   TYPE   PHASE      DURATION   AGE
test-password-reset    user   pending               0s
test-password-reset    user   running               2s
test-password-reset    user   done       5s         5s
```

Press `Ctrl+C` to stop watching once it reaches `done`.

## Step 6: View the Output

```bash
kubectl get query test-password-reset \
  -o jsonpath='{.status.responses[0].content}'
```

Example output:

```
To reset your password, please follow these steps:

1. Go to the login page
2. Click the "Forgot Password" link
3. Enter your registered email address
4. Check your email for a password reset link
5. Click the link and create a new secure password
6. Log in with your new password

If you don't receive the email within 5 minutes, please check your spam folder.
```

## Step 7: View Detailed Information

```bash
kubectl describe query test-password-reset
```

You'll see the `Phase`, the response (agent name + content), `Token Usage` (input / output / total), and start/end times.

## Step 8: Monitor in the Ark Dashboard

Launch the dashboard:

```bash
ark dashboard
```

The command opens it in your browser and handles port-forwarding for you. In the dashboard:

1. Navigate to the **Queries** view
2. Find `test-password-reset` in the list
3. Open it to see:
   - The input message
   - The agent's response
   - The execution timeline
   - Token usage
   - The model used

## Step 9: Test Different Scenarios

```bash
cat > queries/test-billing.yaml <<'EOF'
apiVersion: ark.mckinsey.com/v1alpha1
kind: Query
metadata:
  name: test-billing
spec:
  input: "How can I upgrade my subscription plan?"
  target:
    type: agent
    name: support-agent
EOF

kubectl apply -f queries/test-billing.yaml
kubectl get query test-billing \
  -o jsonpath='{.status.responses[0].content}'
```

## Step 10: Add a Triage Agent (Optional)

Add a second agent that classifies requests before they reach the support agent.

```bash
cat > agents/triage-agent.yaml <<'EOF'
apiVersion: ark.mckinsey.com/v1alpha1
kind: Agent
metadata:
  name: triage-agent
spec:
  description: Categorizes and routes customer inquiries
  modelRef:
    name: default
  prompt: |
    You are a triage agent that categorizes customer inquiries.

    Categories:
    - technical: Password resets, login issues, bugs
    - billing: Subscription, payment, invoices
    - sales: Upgrades, new features, pricing

    Respond with just the category name.
EOF

kubectl apply -f agents/triage-agent.yaml
```

## Step 11: Create a Team

Combine both agents into a sequential team — triage runs first, then support answers.

```bash
cat > teams/support-team.yaml <<'EOF'
apiVersion: ark.mckinsey.com/v1alpha1
kind: Team
metadata:
  name: support-team
spec:
  description: Triage then answer
  strategy: sequential
  members:
    - type: agent
      name: triage-agent
    - type: agent
      name: support-agent
EOF

kubectl apply -f teams/support-team.yaml
```

Send a query to the team:

```bash
cat > queries/team-test.yaml <<'EOF'
apiVersion: ark.mckinsey.com/v1alpha1
kind: Query
metadata:
  name: team-test
spec:
  input: "I want to upgrade my plan and my payment failed"
  target:
    type: team
    name: support-team
EOF

kubectl apply -f queries/team-test.yaml

kubectl get query team-test -o jsonpath='{.status.responses}' | jq
```

## Summary

You generated, deployed, tested, and monitored a real Ark workflow:

1. Wrote an Agent that answers support questions
2. Verified it with a one-shot Query
3. Inspected results via `kubectl` and the dashboard
4. Added a second agent and combined the two into a sequential Team
