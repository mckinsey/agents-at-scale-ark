# A2A V1 Next Actions

This roadmap lists follow-on work after experimental A2A V1.

Version posture:

- Runtime interoperability baseline remains **v0.3**.
- V1 RC rollout is through explicit adapters and serializers.
- Default non-experimental paths stay unchanged until explicit cutover approval.

Tracking notes:

- This page tracks alignment with existing issues.
- It does not imply closure of any issue.
- Default non-experimental paths stay unchanged unless explicitly approved.

## Prioritization Rules

- Keep changes additive and removable from experimental boundaries.
- Prioritize interop safety and regression coverage before broadening feature surface.
- Treat provider-specific APIs as edge adapters, not internal transport contracts.

## V1 Cutover Readiness Checklist

Use this checklist before changing the default runtime wire baseline from v0.3 to V1.

| Gate | Measurable criteria | Rollback signal | Tracking |
| --- | --- | --- | --- |
| SDK and tooling parity | Ark API gateway and internal adapters pass dual-version read tests and explicit v0.3/V1 serialization tests in CI for two consecutive release branches | Any regression in v0.3 default-path behavior or missing serializer coverage blocks cutover | [#1059](https://github.com/mckinsey/agents-at-scale-ark/issues/1059), [#965](https://github.com/mckinsey/agents-at-scale-ark/issues/965) |
| Protocol conformance | Streaming/task lifecycle compatibility suite passes for both payload versions with no critical failures for 14 consecutive days | Stream lifecycle mismatch, task state drift, or ID-correlation loss triggers immediate rollback to v0.3 default | [#530](https://github.com/mckinsey/agents-at-scale-ark/issues/530), [#1059](https://github.com/mckinsey/agents-at-scale-ark/issues/1059) |
| Extension compatibility | Delegated tool extension and structured parameter flows remain stable across v0.3 and V1 adapter modes | Delegated call correlation loss or `valueFrom` parameter regressions require reverting default to v0.3 | [#557](https://github.com/mckinsey/agents-at-scale-ark/issues/557), [#558](https://github.com/mckinsey/agents-at-scale-ark/issues/558), [#1082](https://github.com/mckinsey/agents-at-scale-ark/issues/1082) |
| Operational rollback | A single runtime switch restores v0.3 default serialization/parsing paths without code changes | Inability to restore v0.3 behavior in one deployment cycle blocks rollout | [#1059](https://github.com/mckinsey/agents-at-scale-ark/issues/1059) |

### Deprecation Timing Policy

- Keep dual-shape adapter support available for at least **two minor releases** after default cutover.
- Mark v0.3 default-path deprecation in docs and release notes at cutover time.
- Remove v0.3 default-path emission only after dual-release stability criteria and rollback criteria remain green.
