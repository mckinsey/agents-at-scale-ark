# A2A Experimental V1 Implementation

This document defines what is included in A2A experimental V1 and how to operate it without affecting default query execution paths.

## Version Contract

- Current runtime wire baseline is **A2A v0.3**.
- V1 RC support is implemented through **bounded adapter layers**.
- Default non-experimental behavior stays unchanged.

This means V1 work in this document is migration scaffolding, not a production wire cutover.

## Scope

V1 includes:

- Native A2A task/message transport in experimental mode.
- Additive multimodal conversion at A2A adapter boundaries.
- Task-first delegated streaming and delegated-tool correlation metadata.
- Agent-as-tool structured delegation surfaces (`message`, `history`, `contextId`, `input` fallback).

V1 does not replace default Chat Completions or compat execution paths.

## Opt-In Enablement

Enable experimental behavior with the annotation:

```yaml
metadata:
  annotations:
    ark.mckinsey.com/a2a-experimental-enabled: "true"
```

Apply it to resources that should use experimental A2A behavior (agent, team, tool target, query).

## V1 Boundary Contract

| Boundary | V1 behavior | Default behavior |
| --- | --- | --- |
| `message_conversion_experimental.go` | Experimental converters preserve text/image file parts across A2A and OpenAI compat messages | Legacy converters remain text-first |
| `openai_a2a_model_adapter.go` + `a2a_execution_local.go` | Experimental adapter call sites use experimental converters only | Non-experimental call sites are unchanged |
| `execution_engine.go` | Native A2A fallback can decode compat `contentParts` when experimental mode is enabled | Shared compat decode remains string-only |
| `provider_bedrock.go` | Experimental path extracts array content parts (`text`, `image_url`) and projects to Bedrock content string | Default extraction remains `OfString`-only |
| `memory_http.go` | Native A2A flows use native message APIs where available | `GetMessages(...)` remains legacy OpenAI conversion |
| `executor-langchain/a2a_executor.py` | Native payload supports image file part projection to `image_url` content blocks | Compat text behavior remains unchanged |

## Lossless Rules for V1 Adapters

- Preserve part order for `parts[]` and content arrays.
- Preserve `messageId`, `taskId`, and `contextId` when present.
- Preserve task lifecycle state transitions in streaming mode.
- Preserve delegated tool extension metadata (`https://ark.mckinsey.com/extensions/delegated-tool/v1`).
- Do not silently widen default-path behavior outside experimental call sites.

## Known Limitations

- Legacy shared conversion helpers remain text-first by design.
- Bedrock experimental conversion currently projects multimodal parts into string content, not provider-native binary blocks.
- OpenAI Responses API adapter is not part of V1 (tracked separately).
- Python native payload tests depend on local service dependencies and build artifacts.

## Rollback

Rollback remains bounded to additive experimental surfaces:

1. Remove experimental converter helpers and call sites.
2. Remove experimental-only decode branches in A2A-native boundaries.
3. Remove experimental-only tests and docs.
4. Keep default compat/completions paths unchanged.
