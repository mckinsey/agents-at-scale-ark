# RFC: Experimental A2A native execution

<Callout type="warning">
**Experimental / RFC.** This feature is subject to change or withdrawal without notice. Do not depend on it for production workloads without accepting the risk of breaking changes.
</Callout>

| Field | Value |
|-------|-------|
| **Status** | Experimental |
| **Author** | Drew Foxall |
| **Date** | 2026-02-12 |
| **PRs** | [#1060](https://github.com/mckinsey/agents-at-scale-ark/pull/1060), [#1092](https://github.com/mckinsey/agents-at-scale-ark/pull/1092) |
| **Annotation** | `ark.mckinsey.com/a2a-experimental-enabled` |

## Problem

Ark needs an A2A experiment that is isolated from the default OpenAI path and removable without side effects.

The previous approach mixed A2A and OpenAI internally. That created hidden overlap, made rollback harder, and reduced composability for non-OpenAI agent stacks.

## Goal

A separate execution path where `protocol.Message` flows end-to-end -- from query input through agent/team execution, delegation, memory, and response serialization -- with zero A2A-to-OpenAI conversion inside Ark's control plane.

The default OpenAI path must remain unchanged when the flag is disabled: no extra conversions, no extra K8s API calls, no behavioral differences.

## Architecture

When `ark.mckinsey.com/a2a-experimental-enabled: "true"` is active:

- The controller dispatches to `executeAgentA2A` / `executeTeamA2A` (separate from `executeAgent` / `executeTeam`).
- Query input is parsed via `GetQueryInputA2AMessages` (returns `[]protocol.Message` directly).
- Agent execution routes through capability resolution:
  - reserved `a2a` engine -> `A2AExecutionEngine.ExecuteNative`
  - known native external engines -> native `ExecutionEngine` payload mode on `/execute-a2a`
  - known OpenAI-compatible executors -> boundary compat wrapper
- Team strategies use parallel A2A methods (`executeSequentialA2A`, `executeRoundRobinA2A`, etc.).
- Memory reads/writes use `AddA2AMessages` / `GetA2AMessages`.
- Tool delegation uses `ExecuteA2A` / `ExecuteNative` and returns structured A2A metadata.
- Response serialization writes `ExecutionResult.A2AMessages` directly.
- A2A extensions are activated through the `A2A-Extensions` HTTP header, derived from negotiated extension URIs in the outbound message.

When the flag is disabled:

- The controller dispatches to `executeAgent` / `executeTeam` (unchanged OpenAI path).
- `GetQueryInputMessages` parses OpenAI input only (no A2A branches).
- `AddMessages` writes OpenAI format only (no context sniffing).
- `GetMessages` reads records and converts via `unmarshalMessageRobust` -> `A2AToOpenAIMessage` (handles both legacy and A2A records).
- No experimental functions are called.

## Enable the experiment

Set the annotation `ark.mckinsey.com/a2a-experimental-enabled: "true"` on agent, team, or query resources.

```yaml
apiVersion: ark.mckinsey.com/v1alpha1
kind: Agent
metadata:
  name: my-agent
  annotations:
    ark.mckinsey.com/a2a-experimental-enabled: "true"
spec:
  # ...
```

When the annotation is absent or set to `"false"`, the OpenAI path is used and behavior is unchanged.

## Runtime requirements

When experimental mode is enabled for a workload:

- Target type must be `agent` or `team`.
- Participating agents must resolve to one of:
  - reserved `a2a` execution engine
  - known native external execution engine type (currently `a2a-langchain`)
  - local or external known OpenAI-compatible executor via boundary compat wrapper
- Unknown execution engine types fail fast with a compatibility error.
- Native external engines are expected to accept and emit A2A messages.
- Compat-wrapped local execution keeps existing tool behavior, including MCP-backed filesystem tools.

## Composability model

Any agent system that speaks A2A can participate through an execution engine, regardless of underlying model provider.

Examples:

- A LangChain-based A2A engine
- A Claude-backed engine
- A Gemini-backed engine
- A custom internal engine

Teams can compose heterogeneous members as long as each member is A2A-compatible.

## Fail-fast behavior

When experimental mode is enabled:

- A2A transport failures are returned immediately.
- Unknown execution engines fail fast instead of silently falling back.
- The OpenAI model execution path (`Model.ChatCompletion`) rejects calls when the experimental flag is active unless execution is explicitly routed through the compat wrapper.
- Native response serialization fails if `ExecutionResult` does not contain A2A-native messages.
- Native event streams do not emit OpenAI completion chunks at finalize time.
- Native error events use `TaskStatusUpdateEvent` with `state=failed`, not plain messages.

## A2A gateway bridge (ark-api)

The `ark-api` service exposes an A2A JSON-RPC gateway that discovers Ark agents, builds A2A AgentCards, and routes incoming A2A requests to Kubernetes Query CRDs. When the experimental annotation is present on the target agent, the gateway resolves the flag (with a 30-second TTL cache) and propagates it as an annotation on the created Query resource. The controller then dispatches based on the annotation. The gateway persists per-agent task stores across dynamic route refreshes to preserve A2A task lifecycle continuity.

## External behavior by mode

| Surface | Disabled (default) | Enabled (experimental) |
|---------|-------------------|----------------------|
| Query input for agent/team | `GetQueryInputMessages` (OpenAI) | `GetQueryInputA2AMessages` (A2A) |
| Internal execution payload | `Agent.Execute` / `Team.Execute` | `Agent.ExecuteA2A` / `Team.ExecuteA2A` with capability routing |
| Executor compatibility | N/A | reserved `a2a`, native external types (`a2a-langchain` via `/execute-a2a`), or known OpenAI compat wrapper (`langchain` via `/execute`) |
| `response.raw` | OpenAI JSON | A2A JSON |
| Memory writes | `AddMessages` (OpenAI JSON) | `AddA2AMessages` (A2A JSON) |
| Memory reads | `GetMessages` (OpenAI) | `GetA2AMessages` (A2A, reads both formats) |
| Delegation payloads | `input` string | A2A `message`/`history` + metadata |

## Memory compatibility

`unmarshalMessageRobust()` reads both legacy OpenAI `{"role","content"}` records and A2A `{"role","parts":[...]}` records. Existing OpenAI memory remains readable after enabling the experiment.

## Revert path

Disabling the annotation restores the default path at runtime.

If the experiment is withdrawn, removal is isolated to these additive functions (no modifications to the OpenAI path required):

| Component | Functions to remove |
|-----------|-------------------|
| Controller | `dispatchAgent`, `dispatchTeam`, `executeAgentA2A`, `executeTeamA2A`, `loadInitialA2AMessages` |
| Agent | `ExecuteA2A`, `executeAgentA2A`, `executeWithA2AExecutionEngineNative`, compat/native external capability routing |
| Team | `ExecuteA2A`, `executeSequentialA2A`, `executeRoundRobinA2A`, `executeSelectorA2A`, `executeGraphA2A`, `executeMemberAndAccumulateA2A`, `executeTeamMemberA2A` |
| A2A engine | `ExecuteNative`, `buildA2AMessagesFromResponse` |
| Memory | `AddA2AMessages`, `GetA2AMessages` (interface + implementations) |
| Query input | `GetQueryInputA2AMessages` |
| Helpers | `PrepareA2AExecutionMessages`, `PrepareA2ANewMessagesForMemory`, `ExtractA2ATextFromMessage`, `ExtractA2AUserMessageContent` |
| Tool delegation | A2A branches in `AgentToolExecutor.Execute`, `TeamToolExecutor.Execute` |
| ExecutionResult | `A2AMessages` field |
| Capability split | `executor_capability.go`, `a2a_execution_compat.go`, `Agent.resolvedCapability`, `ExecutionEngineClient.ExecuteA2A` |
| LangChain executor | `services/executor-langchain/src/langchain_executor/a2a_executor.py`, `services/executor-langchain/src/langchain_executor/app.py` (`/execute-a2a`) |
| SDK/contract | `ExecutionEngineRequest`/`ExecutionEngineResponse` A2A fields, `ExecutorApp.setup_a2a_route` |
| Helm registration | optional `a2a-langchain` `ExecutionEngine` template (`services/executor-langchain/chart/templates/executionengine.yaml`) |

The default OpenAI path (`executeAgent`, `executeTeam`, `Agent.Execute`, `Team.Execute`, `GetQueryInputMessages`, `AddMessages`, `GetMessages`) remains intact and requires no changes on removal.
