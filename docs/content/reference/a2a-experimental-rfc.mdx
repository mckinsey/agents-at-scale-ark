# RFC: Experimental A2A internal transport

<Callout type="warning">
**Experimental / RFC.** This feature is subject to change or withdrawal without notice. Do not depend on it for production workloads without accepting the risk of breaking changes.
</Callout>

| Field | Value |
|-------|-------|
| **Status** | Experimental |
| **Author** | Drew Foxall |
| **Date** | 2026-02-11 |
| **PRs** | [#1060](https://github.com/mckinsey/agents-at-scale-ark/pull/1060), [#1092](https://github.com/mckinsey/agents-at-scale-ark/pull/1092) |
| **Annotation** | `ark.mckinsey.com/a2a-experimental-enabled` |

## Problem

Ark needs an A2A experiment that is isolated from the default OpenAI path and removable without side effects.

The previous approach mixed A2A and OpenAI internally. That created hidden overlap, made rollback harder, and reduced composability for non-OpenAI agent stacks.

## Proposal

When `ark.mckinsey.com/a2a-experimental-enabled: "true"` is active for an agent/team execution:

- Ark uses `protocol.Message` end-to-end for query input, execution, delegation, memory I/O, and response serialization.
- Ark runs a separate experimental execution path (`ExecuteA2A` / `ExecuteNative`) and keeps the default OpenAI path unchanged.
- Ark requires agents to have an A2A-compatible execution engine and rejects local model execution in this mode.

The OpenAI path remains the default and is unchanged when the flag is disabled.

## Enable the experiment

Set the annotation `ark.mckinsey.com/a2a-experimental-enabled: "true"` on agent, team, or query resources.

```yaml
apiVersion: ark.mckinsey.com/v1alpha1
kind: Agent
metadata:
  name: my-agent
  annotations:
    ark.mckinsey.com/a2a-experimental-enabled: "true"
spec:
  # ...
```

When the annotation is absent or set to `"false"`, the legacy OpenAI transport is used and behavior is unchanged.

## Runtime requirements

When experimental mode is enabled for a workload:

- Target type must be `agent` or `team`.
- Participating agents must define an `executionEngine`.
- Local execution (no engine) is rejected with a validation error at execution time.
- Engines used in this path must be A2A-compatible.

This makes Ark transport-neutral in the experiment: Ark orchestrates with A2A, and execution engines convert to provider-specific model formats internally.

## Composability model

Any agent system that speaks A2A can participate through an execution engine, regardless of underlying model provider.

Examples:

- A LangChain-based A2A engine
- A Claude-backed engine
- A Gemini-backed engine
- A custom internal engine

Teams can compose heterogeneous members as long as each member is A2A-compatible.

## Fail-fast behavior

When experimental mode is enabled:

- A2A transport failures are returned immediately.
- No implicit fallback to local OpenAI execution is allowed.
- The OpenAI model execution path is not used for experimental agent/team execution.

## External behavior by mode

| Surface | Disabled (default) | Enabled (experimental) |
|---------|-------------------|----------------------|
| Query input for agent/team | OpenAI input parsing | Native A2A parsing |
| Internal execution payload | OpenAI message path | `protocol.Message` path |
| `response.raw` | OpenAI JSON | A2A JSON |
| Memory writes | OpenAI JSON | Native A2A JSON |
| Memory reads | OpenAI JSON | Reads both OpenAI and A2A records |
| Delegation payloads | `input` string | A2A `message`/`history` + metadata |

## Memory compatibility

`unmarshalMessageRobust()` reads both legacy OpenAI records and A2A records. Existing OpenAI memory remains readable after enabling the experiment.

## Revert path

Disabling the annotation restores the default path at runtime.

If the experiment is withdrawn, removal is isolated to the experimental branch functions:

- `GetQueryInputA2AMessages`, `executeAgentA2A`, `executeTeamA2A`
- `Agent.ExecuteA2A`, `Team.ExecuteA2A`, `A2AExecutionEngine.ExecuteNative`
- `MemoryInterface` A2A methods and native serialization branches

The default OpenAI path remains intact.
