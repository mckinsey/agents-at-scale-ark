# A2AServer

An `A2AServer` connects Ark to a remote [Agent-to-Agent (A2A) protocol](https://a2a-protocol.org) server. Ark connects to the server, discovers the agents it hosts, and creates an [Agent](/reference/resources/agent) resource for each one — wired to the `a2a` execution engine so ordinary [queries](/reference/resources/query) can target them. Each dispatched query then produces an [A2ATask](/reference/resources/a2atask) that Ark polls until the remote agent finishes.

> **API version:** `A2AServer` is served under **`ark.mckinsey.com/v1prealpha1`** — not the `v1alpha1` group used by most Ark resources (Agent, Query, Model, …). Set `apiVersion: ark.mckinsey.com/v1prealpha1` on every A2AServer manifest.

## Spec

```yaml
apiVersion: ark.mckinsey.com/v1prealpha1     # note: v1prealpha1, not v1alpha1
kind: A2AServer
metadata:
  name: aws-operator-agent
spec:
  # --- Required ----------------------------------------------------------
  # Endpoint of the A2A server. Inline 'value', or 'valueFrom' with
  # serviceRef / configMapKeyRef / secretKeyRef.
  address:
    value: http://ark-agentcore-bridge.default.svc.cluster.local:80/a2a/agent/aws_operator_agent

  # --- Optional ----------------------------------------------------------
  description: AWS operations agent with read-only access to AWS services
  # HTTP headers sent on every request, e.g. for authentication. Each value
  # is inline or sourced from a Secret/ConfigMap via valueFrom.
  headers:
    - name: Authorization
      value:
        valueFrom:
          secretKeyRef:
            name: a2a-credentials
            key: token
  pollInterval: 1m                            # how often to poll the server; default '1m'
  timeout: 5m                                 # A2A agent execution timeout; inherits Query.spec.timeout when unset
  # Which URL Ark calls for A2A requests: 'address' (default), 'cardPath', or
  # 'cardUrl'. See "Endpoint resolution" below.
  endpointResolution: cardPath
  # Hosts the agent card may redirect requests to, used only when
  # endpointResolution is 'cardUrl'. '*.' matches one level of subdomain.
  allowedEndpointHosts:
    - agents.example.com
    - '*.a2a.example.com'
```

## Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `spec.address` | `ValueSource` | yes | Endpoint of the A2A server. Supports an inline `value`, or `valueFrom` with `serviceRef` (`name`, plus optional `namespace`, `port`, `path`), `configMapKeyRef`, or `secretKeyRef`. |
| `spec.headers[]` | list of `Header` | no | HTTP headers sent on every request to the server, typically for authentication. Each entry has a `name` and a `value` that is inline or sourced via `valueFrom` (`secretKeyRef`, `configMapKeyRef`, or `queryParameterRef`). |
| `spec.description` | string | no | Human-readable description of the server. Propagated onto the Agent resources Ark creates. |
| `spec.pollInterval` | duration | no | How often the controller polls the server for updates. Default `1m`. |
| `spec.timeout` | duration | no | Timeout for A2A agent execution (`30s`, `5m`, `1h`). When unset, execution inherits the deadline from [`Query.spec.timeout`](/reference/resources/query#timeout), falling back to `5m` if the caller set no deadline. |
| `spec.endpointResolution` | string | no | Which URL Ark calls for A2A requests. `address` (default) uses `spec.address` unchanged. `cardPath` keeps the scheme, host and port from `spec.address` and takes only the path from the agent card. `cardUrl` uses the agent card URL as written. See [Endpoint resolution](#endpoint-resolution). |
| `spec.allowedEndpointHosts[]` | list of string | no | Hosts the agent card may redirect requests to when `endpointResolution` is `cardUrl`. The host of `spec.address` is always allowed. Entries are hostnames, optionally prefixed with `*.` to match one level of subdomain. Ignored in the other modes. |

## Discovery and created agents

When an A2AServer is created, the controller:

1. **Discovers agents.** It connects to `spec.address` and fetches the server's agent card, trying `/.well-known/agent-card.json` (A2A v0.3+) first, then falling back to `/.well-known/agent.json` (A2A v0.2.x).
2. **Creates an Agent per discovered agent.** Each generated [Agent](/reference/resources/agent) has an owner reference to the A2AServer, `executionEngine.name: a2a`, and annotations recording the source server, resolved address, and discovered skills. A2A agents carry no `modelRef` — the remote server owns the model.
3. **Monitors health.** The controller re-polls on `spec.pollInterval` and keeps the `Ready` and `Discovering` conditions current.

Example Agent generated from the A2AServer above:

```yaml
apiVersion: ark.mckinsey.com/v1alpha1
kind: Agent
metadata:
  name: aws-operator-agent
  annotations:
    ark.mckinsey.com/a2a-server-name: aws-operator-agent
    ark.mckinsey.com/a2a-server-address: http://ark-agentcore-bridge.default.svc.cluster.local:80/a2a/agent/aws_operator_agent
    ark.mckinsey.com/a2a-server-skills: '[{"name":"describe_ec2_instances","description":"List and describe EC2 instances in the account"}]'
spec:
  description: AWS operations agent with read-only access to AWS services
  prompt: You are aws_operator_agent. AWS operations agent with read-only access to AWS services
  executionEngine:
    name: a2a                                 # no modelRef — the remote A2A server owns the model
```

## Endpoint resolution

The agent card the server returns carries its own `url` field, the endpoint the A2A spec says clients should send requests to. By default Ark ignores it and keeps calling `spec.address`, because a server's card commonly advertises a URL that is not reachable from inside the cluster (`http://localhost:8000`, a public ingress hostname, or a placeholder). `spec.endpointResolution` opts a single A2AServer into trusting the card:

| Mode | Behaviour |
| --- | --- |
| `address` (default) | Requests go to `spec.address` unchanged. The card `url` is ignored. |
| `cardPath` | Scheme, host and port come from `spec.address`, the path comes from the card. Use this when the server is correct about *where* its RPC endpoint sits but wrong about the hostname, which is the usual Kubernetes case. Query strings and fragments on the card URL are dropped. |
| `cardUrl` | The card URL is used as written. Allowed only when its host matches the host of `spec.address`, or is listed in `spec.allowedEndpointHosts`. |

`cardUrl` is the only mode that can move requests to a different host, and it is gated because `spec.headers` travel with the request: a card that repoints the endpoint would send your Secret-sourced credentials to whatever host it names. The card is refetched on every `spec.pollInterval`, so this is a standing delegation, not a one-time decision. `spec.allowedEndpointHosts` is therefore per-resource, so trusting one server does not trust the others.

Rejected overrides never break a working server. Ark falls back to `spec.address`, sets the `EndpointOverride` condition to `False` with the reason (`CrossOriginNotAllowed`, `InvalidAgentCardURL`, `NoAgentCardURL`, or `InvalidAddress`), records the rejected URL in `status.rejectedEndpoint`, and emits an `EndpointOverrideRejected` warning event. When an override is applied, `EndpointOverride` is `True` with reason `AgentCardEndpointApplied`.

### Transport

Ark speaks JSON-RPC only. The endpoint it picks is the card's JSON-RPC interface: `url` when `preferredTransport` is `JSONRPC` or unset, otherwise the first `JSONRPC` entry in `additionalInterfaces`. A card that declares no JSON-RPC interface at all is a hard error, since Ark cannot talk to it: `Ready` goes `False` with reason `UnsupportedTransport`, an `UnsupportedTransport` warning event is emitted, and no Agent resources are created or updated for that server.

## Conversation context

Ark does not hydrate conversation history into the message it sends a discovered agent: a query targeting one sends only that query's current input, even when memory is active. Threading is opt-in — set the `ark.mckinsey.com/a2a-context-id` annotation on the query and Ark forwards that value as the A2A `contextId`, so a server that keys state on it links successive calls. Without the annotation Ark sends no `contextId` and each call stands alone. `spec.conversationId` threads the completions executor and named execution engines; it does not reach A2AServer agents. See [A2A Queries → Stateful Messages](/developer-guide/queries/a2a-queries#stateful-messages) for a worked example.

An agent running as a [Team](/reference/resources/team) member is the exception: Ark renders the accumulated team transcript into the message, so the member sees earlier members' turns without depending on server-side retention.

## Status

```yaml
status:
  conditions:
    - type: Ready                             # server reachable and operational
      status: "True"
      reason: AgentDiscovered
      message: Successfully discovered agent
    - type: Discovering                       # agent discovery in progress
      status: "False"
      reason: DiscoveryComplete
      message: Agent discovery completed
    - type: EndpointOverride                  # only present when endpointResolution != 'address'
      status: "True"
      reason: AgentCardEndpointApplied
      message: Using agent card endpoint http://ark-agentcore-bridge.default.svc.cluster.local:80/rpc
  lastResolvedAddress: http://ark-agentcore-bridge.default.svc.cluster.local:80/a2a/agent/aws_operator_agent
  lastResolvedEndpoint: http://ark-agentcore-bridge.default.svc.cluster.local:80/rpc
```

### Status fields

| Field | Description |
| --- | --- |
| `status.lastResolvedAddress` | The most recently resolved server address (after `spec.address` `valueFrom` resolution). |
| `status.lastResolvedEndpoint` | The endpoint Ark actually sends A2A requests to. Equal to `lastResolvedAddress` in the default `address` mode. |
| `status.rejectedEndpoint` | The agent card URL Ark refused to use, set when an override is rejected and cleared when it is not. |
| `status.conditions[]` | Standard Kubernetes conditions. `Ready` indicates the server is reachable and operational; `Discovering` indicates agent discovery is in progress; `EndpointOverride` reports whether the agent card endpoint was applied, and appears only when `spec.endpointResolution` is not `address`. |

### Print columns

`kubectl get a2aservers` prints:

| Column | Source |
| --- | --- |
| `NAME` | `.metadata.name` |
| `READY` | `Ready` condition status |
| `DISCOVERING` | `Discovering` condition status |
| `ADDRESS` | `.status.lastResolvedAddress` |
| `ENDPOINT` | `.status.lastResolvedEndpoint` |
| `AGE` | `.metadata.creationTimestamp` |
