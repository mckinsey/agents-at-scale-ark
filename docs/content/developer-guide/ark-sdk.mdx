# ARK SDK

The ARK Python SDK provides programmatic access to ARK Kubernetes resources.

## Installation

Install via `uv` or `pip`:

```bash
# Install via uv:
uv add "ark-sdk @ https://github.com/mckinsey/agents-at-scale-ark/releases/download/v0.1.31/ark_sdk-0.1.31-py3-none-any.whl"

# or pip:
pip install https://github.com/mckinsey/agents-at-scale-ark/releases/download/v0.1.31/ark_sdk-0.1.31-py3-none-any.whl
```

Or directory add to your `pyproject.toml`:

```toml
[tool.uv.sources]
ark-sdk = { url = "https://github.com/mckinsey/agents-at-scale-ark/releases/download/v0.1.31/ark_sdk-0.1.31-py3-none-any.whl" }
```

Or `requirements.txt`:

```
ark-sdk @ https://github.com/mckinsey/agents-at-scale-ark/releases/download/v0.1.31/ark_sdk-0.1.31-py3-none-any.whl
```

## Updating Types When CRDs Change

ARK uses Kubernetes CRDs as the source of truth. When CRDs change, types must be updated through the stack.

Changes to the CRDs must be reflected in the Ark SDK, these changes must then be reflected in consumers of the SDK such as the Ark APIs, and consumers of those APIs, such as the Ark dashboard.

Mechanically, the process works like this:

```bash
# Changes are made in the ark CRDs at:
#   config/crd/bases/*.yaml:

# The Python SDK is regenerated from the CRDs. The CRDs are converted into 
# an OpenAI spec and then this regenerated the ark sdk types:
make ark-sdk

# Consumers of the ark api update their code. When a CRD change is made and the
# sdk is regenerated, the ark-api models must be updated (manually).
# After this, the ark-api can be built:
make ark-api-build

# This genreated the services/ark-api/openapi.json, based on the FastAPI models.

# Finally, the ark dashboard can have its Typescript types automatically updated
# based on the new ark-api routes and models:
cp ../../ark-api/openapi.json ../out/
npm run generate:api

# This generate:
# lib/api/generated/types.ts


## Local Development Workflow

When developing new functionality in `ark-sdk`, follow this workflow:

### 1. Make Changes in ark-sdk based on the requirement:

Add your new functionality to the appropriate overlay files:

```bash
# Example structure for new functionality
lib/ark-sdk/gen_sdk/overlay/python/ark_sdk/
├── your_new_client.py        # Add your client class
├── models/
│   └── your_models.py        # Add your data models
├── pyproject.toml           # Add any new dependencies
└── __init__.py              # Export your new classes
```

**Key files to modify:**
- **Client classes** → Add to `lib/ark-sdk/gen_sdk/overlay/python/ark_sdk/`
- **Data models** → Add to `lib/ark-sdk/gen_sdk/overlay/python/ark_sdk/models/`
- **Dependencies** → Update `pyproject.toml`
- **Generated clients** → Modify `python_sdk.py` to inject your client

### 2. Build Local Wheel File

Generate the ark-sdk with your changes:

```bash
# Clean previous builds
rm -rf out/ark-sdk

# Build ark-sdk with your changes
make ark-sdk-build

# This creates:
# out/ark-sdk/py-sdk/dist/ark_sdk-<version>-py3-none-any.whl
```

### 3. Test Your Changes

Copy the wheel to your consuming service for testing and use the new ark-sdk functionality

```bash
# Copy wheel to your service (e.g., ark-api)
cp out/ark-sdk/py-sdk/dist/ark_sdk-*.whl services/ark-api/out/

# Test with devspace
devspace dev
```

```python
# Example: Using new ark-sdk functionality
from ark_sdk.your_new_client import YourNewClient
from ark_sdk.models.your_models import YourModel, YourRequest

# Initialize your client
client = YourNewClient(namespace="default")

# Use your new functionality
result = client.your_new_method()
```

## Production Deployment Workflow

### 1. Automatic PyPI Deployment

The production deployment happens automatically via GitHub Actions:

```yaml
# .github/workflows/deploy.yml triggers on:
# - Manual workflow_dispatch with version input
# - Release creation
# - Tag push (e.g., v0.1.35)

jobs:
  deploy-to-pypi:
    - Builds ark-sdk wheel
    - Runs all tests
    - Publishes to PyPI with new version
```

**How to trigger deployment:**
1. **Manual:** Go to Actions → Deploy → Run workflow → Enter version
2. **Release:** Create a GitHub release with version tag
3. **Automatic:** Push to main branch (if configured)

### 2. Update Consuming Services

After PyPI deployment, update consuming services to use the new version:

```toml
# services/your-service/pyproject.toml
dependencies = [
    "ark-sdk==0.1.35",  # Update to new version
    # ... other deps
]
```

### 3. Deploy Consuming Services

Deploy your consuming service with the new ark-sdk dependency:

```bash
# Build and deploy your service
make your-service-build
devspace deploy

# Or via GitHub Actions deploy workflow
```

## Deployment Order

1. **ark-sdk changes** → Build → Test → Deploy to PyPI
2. **Consuming services** → Update dependencies → Build → Deploy
3. **Other services** → Update as needed

## Rollback Strategy

```bash
# If issues occur, rollback consuming service dependency:
# In pyproject.toml:
dependencies = [
    "ark-sdk==0.1.34",  # Rollback to previous version
]

# Rebuild and redeploy
make your-service-build
devspace deploy
```
